## 3. بوابات الجودة قبل النشر

لا يُسمح بالنشر إذا فشل `npm run build`، أو فشل فحص عدم التسريب، أو ظهرت ثغرة P0/P1 مفتوحة، أو فشل اختبار RBAC، أو فشلت رحلة طلب واحدة مكررة. ويجب أن تكون أي مخاطرة مقبولة مكتوبة باسم المالك والسبب والموعد.

## 4. تقدير الجهد

| المسار | التقدير |
|---|---:|
| مراجعة الكود وإصلاحات الواجهة الحالية | 0.5–1 يوم |
| اختبار القواعد وRBAC عبر Emulator | 1 يوم |
| Playwright لرحلة المستخدم | 2–3 أيام |
| Playwright للمدير ومكتبة الصور | 2–3 أيام |
| Mock/contract tests لـImgBB | 1 يوم |
| اختبارات الأمان والوصولية | 1–1.5 يوم |
| load/concurrency وLighthouse | 1 يوم |
| CI artifacts والتقارير وtriage | 0.5–1 يوم |
| **الإجمالي الواقعي لفريق صغير** | **9–12 يوم عمل** |

هذه تقديرات تخطيطية وليست وعدًا زمنيًا؛ تتغير وفق توفر حساب اختبار، ثبات بيانات Firestore، وإمكانية تشغيل Firebase Emulator وPlaywright في CI.

## 5. استراتيجية البيئات

تُستخدم بيئة محلية مع Firebase Emulator وmock ImgBB للغالبية. وتُستخدم بيئة staging مرتبطة بمشروع Firebase منفصل أو collections ذات بادئة اختبارية قبل الإنتاج. ولا يُستخدم مفتاح ImgBB الحقيقي إلا في اختبار تكامل محمي قصير، مع تدويره بعد الاختبار إذا ظهر في سجلات أو أدوات مطور.
