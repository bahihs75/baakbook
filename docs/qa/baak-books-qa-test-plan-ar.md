# خطة الاختبار الشاملة — Baak Books

**الإصدار:** 1.0 — 20 أغسطس 2026
**النطاق:** النسخة المنشورة على Cloudflare Pages، واجهة المتجر، لوحة الإدارة، Firestore، Firebase Authentication، وImgBB.
**المرجع التنفيذي:** الكود المحلي في `frontend/index.html` و`frontend/admin.html`، وقواعد `firestore.rules`.
**القيود:** لا تعديل على مستودع Afak Carpet؛ لا Firebase Functions أو Blaze؛ لا اختبار تدميري على البيانات الحية دون نسخة اختبار منفصلة؛ لا وضع مفتاح ImgBB في GitHub.

## 1. الهدف ومعايير النجاح

تهدف الخطة إلى إثبات أن Baak Books يعمل بصورة صحيحة وآمنة وقابلة للاسترداد عبر رحلات الزائر والمدير، بما في ذلك شرائح Hero، البحث والاكتشاف، السلة، الشراء، الهدايا، الكتب التي يمكن اقتناؤها عند الطلب، إعدادات الميزات، إدارة الكتب والتصنيفات والطلبات ورسوم التوصيل، ومكتبة الصور المتصلة بـImgBB.

يُعد الإصدار **جاهزًا للمعاينة** عندما تنجح اختبارات P0 وP1، ويُمنع النشر إذا وُجد خلل مفتوح من نوع P0 أو خلل أمني يتيح قراءة/كتابة بيانات الإدارة دون مصادقة. ويُعد جاهزًا للإنتاج بعد نجاح اختبار الاسترداد، وعدم وجود تسريب لمفتاح ImgBB، وتوثيق أي مخاطر مقبولة.

| مستوى | المعنى | قاعدة القرار |
|---|---|---|
| P0 حرج | فقدان بيانات، وصول غير مصرح، إنشاء طلب خاطئ، أو توقف المتجر | إيقاف النشر فورًا |
| P1 مرتفع | تعطل رحلة شراء/هدية أو إدارة أساسية دون بديل عملي | لا نشر حتى الإصلاح أو قبول موثق |
| P2 متوسط | خلل في حالة أو واجهة مع وجود بديل | يمكن تأجيله بموافقة |
| P3 منخفض | مشكلة نصية أو تجميلية لا تؤثر في العملية | تدخل قائمة التحسين |

## 2. الشخصيات والأدوار ومصفوفة RBAC

الأدوار الحالية ثلاثة: **زائر** غير مسجل، **عميل** يستخدم المتجر دون لوحة إدارة، و**مدير مصادق** عبر Firebase Authentication. لا توجد حاليًا صلاحيات محرر محتوى منفصلة؛ لذلك يجب عدم إنشاء دور رابع ضمن الواجهة قبل تصميم قواعد Firestore الخاصة به.

### اختبارات الوصول السلبية لكل دور

يجب تنفيذ كل اختبار من جهاز/جلسة جديدة، مع حذف الكوكيز أو استخدام نافذة خاصة عند الحاجة.

| ID | الدور | المحاولة | النتيجة المتوقعة |
|---|---|---|---|
| RBAC-01 | زائر | فتح `/admin.html` ثم تنفيذ قراءة `adminSecrets/imgbb` من Console | تظهر شاشة الدخول أو رفض Firebase؛ لا تُعاد قيمة المفتاح |
| RBAC-02 | زائر | كتابة وثيقة في `imageLibrary` | رفض Firestore برسالة صلاحيات |
| RBAC-03 | عميل | تعديل وثيقة كتاب أو إعدادات عبر REST/Firestore | رفض العملية؛ لا يتغير المستند |
| RBAC-04 | عميل | استدعاء تبويب الإدارة بعد تغيير DOM يدويًا | لا تكفي الواجهة لمنح الصلاحية؛ يرفض Firestore العملية |
| RBAC-05 | مدير غير مصادق | إرسال طلب كتابة مع رأس مزيف `Authorization` | رفض؛ لا يُقبل البريد أو الرمز من العميل وحده |
| RBAC-06 | مدير مصادق | قراءة وكتابة بيانات الإدارة | نجاح مع تسجيل العملية وظهور التغيير بعد إعادة التحميل |
| RBAC-07 | مدير مصادق | تسجيل الخروج ثم إعادة تنفيذ طلب سابق | رفض العملية أو انتهاء الجلسة؛ لا تعتمد الصلاحية على الواجهة القديمة |
| RBAC-08 | مدير مصادق | محاولة إدخال HTML/JavaScript في اسم كتاب أو وصف | يُخزن النص كنص، ولا يُنفذ داخل جدول الإدارة أو المتجر |

## 3. خريطة الشاشات والتنقل والتحكمات

### 3.1 واجهة المتجر

الصفحة الرئيسية تحتوي على Hero قابل للإخفاء والتخصيص، شريط تصفح/ميزات، البحث الذكي، شبكة الكتب، النوافذ المنبثقة لتفاصيل الكتاب، السلة، مسارات الاكتشاف والهدايا ومختبر الأفكار، ثم نموذج مراجعة الطلب. يجب اختبار كل عنصر في حالتي التفعيل والإيقاف، وحالة عدم وجود بيانات.

| المنطقة | التحكم/الحالة | الاختبار الأساسي | البديل أو الخطأ |
|---|---|---|---|
| Hero | الأسهم والنقاط والسحب والتبديل التلقائي | ينتقل إلى الشريحة الصحيحة ويحافظ على النص والأزرار | شريحة وحيدة، كل الشرائح غير فعالة، صورة فاشلة، autoplay متوقف |
| Hero | الزر الأساسي والثانوي | يفتح الوجهة المحددة من إعداد الشريحة | رابط مخصص فارغ/غير صالح، زر مخفي، ضغط متكرر |
| البحث | `searchInput` وزر البحث | يرشح العناوين/الوصف/التصنيفات بالنتائج الصحيحة | نص فارغ، رموز خاصة، لا نتائج، إدخال طويل |
| شبكة الكتب | اقرأ عنه، أضف إلى السلة، اقتنه الآن، أهدِ هذا الكتاب | تفتح التفاصيل أو تضيف العنصر بالكمية الصحيحة | مخزون صفر، كتاب عند الطلب، سعر صفر، صورة مفقودة |
| تفاصيل الكتاب | إغلاق، إضافة، شراء، هدية | لا يتكرر العنصر ولا تُفقد بياناته | إغلاق بالنقر خارج النافذة، زر معطل، ضغط سريع |
| السلة | زيادة/تقليل/حذف الكمية | يتغير الإجمالي ويُحذف العنصر عند الصفر | كمية أكبر من المخزون، سلة فارغة، إعادة تحميل |
| إهداء مجموعة | فتح من السلة ثم اختيار المستلم | كل الكتب المحددة تدخل مجموعة هدية واحدة | إلغاء، هاتف ناقص، كتاب عند الطلب، سلة مختلطة |
| التوصيل | مكتب الاستلام/المنزل والولاية/البلدية | تُحسب الرسوم وتظهر في الملخص | منطقة غير معروفة، رسوم مفقودة، تغيير طريقة التوصيل |
| الطلب | متابعة، رجوع، مراجعة، تأكيد | لا يُرسل الطلب قبل اجتياز الحقول، ويظهر رقم الطلب عند النجاح | اتصال مقطوع، طلب مزدوج، بيانات ناقصة، إعادة الإرسال |
| الميزات | إظهار/إخفاء الأقسام | عند الإيقاف تختفي عناصر القسم كاملة؛ عند الإيقاف الكلي يبقى Hero الأساسي | cache قديم، رابط preview، إعادة تحميل |

## 4. التكاملات وعقود البيانات

| التكامل | الاتجاه | عقد البيانات/التحقق | أخطاء وفشل يجب حقنها |
|---|---|---|---|
| Firebase Authentication | المتصفح ↔ Firebase | بريد/كلمة مرور، Firebase ID token، حالة مستخدم مصادق | كلمة مرور خاطئة، token منتهٍ، offline، logout أثناء الطلب |
| Firestore `products` | قراءة عامة/كتابة مدير | `id`, `title`, `category`, `price`, `img`, `stock_quantity`, `availability_type`, `lead_time_*`, flags | وثيقة ناقصة، قيمة سالبة، id مكرر، صلاحية مرفوضة |
| Firestore `categories` | قراءة عامة/كتابة مدير | `name`, `active`, timestamps | تصنيف مكرر، إعادة تسمية مرتبطة بكتب، حذف فاشل |
| Firestore `orders` | إنشاء عميل/قراءة وتعديل مدير | رقم الطلب، عناصر، الإجمالي، بيانات العميل، التوصيل، الهدية، الحالة | إرسال مزدوج، total غير متسق، حالة غير مدعومة، اتصال مقطوع |
| Firestore `deliveryFees` | قراءة عامة/تعديل مدير | `num`, `stop_desk`, `domicile` أرقام غير سالبة | منطقة غير موجودة، قيمة نصية، قيمة سالبة |
| Firestore `settings` | قراءة عامة/تعديل مدير | `features`, `storefront.hero`, timestamps | JSON ناقص، شريحة بلا id، interval خارج الحدود |
| Firestore `imageLibrary` | مدير فقط | `id`, `url`, `display_url`, `name`, dimensions, type, createdAt | URL غير صالح، سجل مكرر، حذف، صورة خارجية لا تستجيب |
| Firestore `adminSecrets/imgbb` | مدير فقط | `apiKey`, timestamps, updatedBy | قراءة زائر، مفتاح فارغ، تغيير المفتاح، logout |
| ImgBB API v1 | المتصفح الإداري ↔ ImgBB | `POST https://api.imgbb.com/1/upload?key=…`, multipart `image`, استجابة `success/data.url` | 400، 401/403، 429، 5xx، timeout، CORS، حجم/نوع غير مقبول |

يُراجع عقد ImgBB مقابل [وثائق ImgBB الرسمية][1]. لا ينبغي اعتبار مفتاح ImgBB سرًا مطلقًا بعد إرساله من المتصفح إلى ImgBB؛ لذلك يجب تقييد استخدامه بحساب المدير، ووضع حد للحجم والنوع، ومراقبة الاستهلاك، وتجديد المفتاح عند الاشتباه بإساءة استخدام.

## 5. رحلات الأعمال من البداية إلى النهاية

### E2E-01 — شراء كتاب متوفر

يبدأ الزائر من الصفحة العامة، يبحث أو يفتح بطاقة كتاب، يضيفه إلى السلة، يراجع الكمية، يختار طريقة التوصيل والمنطقة، يملأ بيانات العميل، يراجع الإجمالي، ثم يؤكد الطلب. يجب أن يظهر رقم طلب واحد، ووثيقة واحدة في `orders`، وإجمالي يساوي مجموع المنتجات والرسوم.

### E2E-02 — شراء كتاب يمكن اقتناؤه عند الطلب

يُعرض الكتاب على أنه قابل للاقتناء عند الطلب، ويظهر زمن التجهيز المسموح به. عند الإضافة لا يُعامل كمخزون متوفر. يجب حفظ نوع التوفر ومدة التجهيز في الطلب، وإظهار ملاحظة مناسبة للعميل والمدير.

### E2E-03 — هدية كتاب من بطاقة المنتج

يضغط العميل «أهدِ هذا الكتاب»، يختار المستلم وطريقة الوصول ويُطلب رقم الهاتف الإلزامي وفق السياسة المعتمدة. يجب أن يظهر الطلب كهدية، وألا تُخلط بيانات المستلم ببيانات المشتري.

### E2E-04 — إهداء مجموعة من السلة

يضيف العميل عدة كتب، يفتح زر إهداء المجموعة، يحدد مستلمًا واحدًا، ثم يكمل المراجعة. يجب حفظ مجموعة هدية واحدة فقط في الإصدار الأول، ومنع وجود مستلمين متعددين في نفس الطلب.

### E2E-05 — إدارة صورة Hero من البداية إلى النهاية

يسجل المدير الدخول، يفتح «مكتبة الصور»، يحفظ مفتاح ImgBB، يختار صورة محلية، يرفعها، يرى السجل في المكتبة، ثم يفتح «إدارة الـHero» ويختار الصورة للشريحة ويحفظ. بعد إعادة تحميل المتجر يجب أن تظهر الصورة في الشريحة.

### E2E-06 — فشل ImgBB ثم التعافي

يستخدم المدير مفتاحًا خاطئًا أو يحاكي استجابة 429/500. يجب أن تظهر رسالة خطأ مفهومة، ولا يُحفظ سجل ناقص في `imageLibrary`. بعد تصحيح المفتاح وإعادة المحاولة يجب نجاح الرفع دون سجلات مكررة.

### E2E-07 — تعديل كتاب واختيار صورة من المكتبة

يفتح المدير كتابًا موجودًا، يضغط «اختيار من المكتبة»، يختار صورة، يحفظ الكتاب، ثم يعيد فتحه. يجب أن يبقى الرابط محفوظًا، وتظهر المعاينة، ولا يتغير أي حقل آخر.

### E2E-08 — إعادة تسمية تصنيف مرتبط بكتب

يعدل المدير اسم تصنيف مستخدم. يجب تحديث التصنيف في وثيقة التصنيف وجميع الكتب المرتبطة داخل batch واحد أو عملية متسقة، مع إظهار رسالة فشل واضحة عند انقطاع العملية.

## 6. مصفوفة أنواع الاختبار

| النوع | الهدف | نطاق التنفيذ | أداة مقترحة |
|---|---|---|---|
| Unit | تطبيع البيانات، حساب الأسعار، حالات Hero، التحقق من الملفات | دوال مستقلة دون شبكة | Vitest أو Jest |
| API/Rules | Firestore rules وطلبات الإدارة | السماح/الرفض لكل مجموعة | Firebase Emulator Suite |
| Integration | Firebase Auth + Firestore + ImgBB | حفظ/قراءة/فشل واسترداد | Playwright + mocks |
| Contract | شكل استجابة ImgBB والوثائق | schema وحقول إلزامية | Zod/JSON Schema |
| UI automation | كل شاشة وزر وحالة | Chromium RTL، سطح مكتب وهاتف | Playwright |
| Load/concurrency | الرفع المتعدد، قراءة الكتب، تأكيد الطلب | 10/25/50 جلسة افتراضية | k6 أو Artillery |
| Security | XSS، صلاحيات، تسريب مفتاح، CSRF-like abuse | جلسات مجهولة ومدير | Playwright + OWASP checks |
| Data integrity | عدم تكرار الطلب، totals، مرجع الصور | Firestore snapshots | Python/Node validators |
| Recovery | retry، offline، timeout، refresh | كل تكامل خارجي | Playwright route abort/delay |
| Accessibility | keyboard، focus، labels، contrast | العامة والإدارة | axe-core + manual keyboard |
| Performance | LCP، JS errors، صور كبيرة | صفحة المتجر واللوحة | Lighthouse/Playwright |

## 8. قواعد البيانات وبيانات الاختبار

تُستخدم مجموعة Firebase اختبارية أو Emulator عند الاختبارات المدمرة. يجب توفير كتاب متوفر، كتاب مخزونه صفر، كتاب عند الطلب بمدة يوم واحد، تصنيف مرتبط بكتابين، رسوم توصيل معروفة، رسوم ناقصة، وصورة محلية سليمة وصورة كبيرة وSVG آمن وSVG يحتوي على script. يجب عدم استعمال الطلب الحقيقي `ORD-0004` في اختبار الحذف أو تغيير الحالة إلا بعد نسخه إلى بيئة اختبار.

## 9. استراتيجية الأتمتة وCI/CD

يُقسم الاختبار إلى طبقات. تبدأ كل Pull Request باختبار الصياغة والبناء والفحوص الثابتة، ثم اختبار قواعد Firestore على Emulator، ثم UI smoke قصير. تُشغّل مجموعة التكامل الكاملة على فرع معاينة منفصل، ويُعاد تشغيل اختبارات الشبكة الفاشلة مرة واحدة فقط مع تسجيل سبب flaky؛ لا يُخفى الفشل بإعادة المحاولة غير المحدودة.

| المرحلة | الاختبارات | بوابة القبول |
|---|---|---|
| Pre-commit | `git diff --check`, static validators, no-secret scan | صفر أخطاء وتسريبات |
| Pull Request | build, unit, rules, Playwright smoke | كل P0/P1 ناجح |
| Preview | رحلات شراء/هدية/إدارة/ImgBB mock | لا خلل حرج |
| Release candidate | full UI, accessibility, performance, recovery | تقرير موقع ومراجعة يدوية |
| بعد النشر | health check، الصفحة العامة، admin login، قراءة Firestore | تنبيه فوري عند الفشل |

تُستخدم mocks لـImgBB في CI حتى لا تستهلك الحصة أو تعتمد على شبكة خارجية. ويُجرى اختبار حقيقي واحد محدود في بيئة معاينة بمفتاح مخصص، مع عدم تسجيل المفتاح أو URL الحذف في السجلات العامة.

## 10. تقليل الاختبارات المتذبذبة وإدارة البيئات

تُستخدم معرفات وبيانات اختبار عشوائية مع بادئة `qa-`، ويُعاد تنظيفها في `afterEach`. لا تعتمد اختبارات UI على `sleep`؛ بل تنتظر حالة DOM أو استجابة Firestore. تُعزل اختبارات ImgBB في mock server، وتُثبت الساعة عند اختبار autoplay والـtimestamps. تُحفظ لقطات الفشل وtrace وconsole log لكل اختبار واجهة فاشل.

## 11. الرصد والتحقق أثناء الاختبار

يجب تسجيل رقم الطلب، نوع العملية، مدة الاستجابة، HTTP status، وسبب الفشل دون تسجيل البريد الكامل أو مفتاح ImgBB أو بيانات المستلم الحساسة. تُراقب مؤشرات: معدل فشل تسجيل الدخول، فشل Firestore، فشل ImgBB، زمن الرفع، نسبة الطلبات المكررة، أخطاء JavaScript، وعدد صور المكتبة. تُطلق التنبيهات عند تكرار فشل ImgBB أو ارتفاع رفض الصلاحيات أو ظهور أخطاء 5xx.

| الإشارة | فحص الاختبار | التنبيه المقترح |
|---|---|---|
| Console error | لا أخطاء غير متوقعة في رحلات P0 | تنبيه عند أي خطأ جديد |
| Firestore permission denied | يرفض العمليات غير المصرح بها فقط | تنبيه عند رفض المدير المصادق |
| ImgBB latency | p95 للرفع ضمن حد عملي | تنبيه عند timeout/429 متكرر |
| Order duplicate | نفس idempotency context لا ينشئ طلبين | P0 عند التكرار |
| UI accessibility | labels وfocus وcontrast | P1 للعناصر الأساسية |

## 12. المخاطر ذات الأولوية

| الخطر | الأثر | الاحتمال | المعالجة |
|---|---|---:|---|
| مفتاح ImgBB ظاهر في المتصفح أثناء الرفع | إساءة استخدام الحصة | متوسط | مدير فقط، حد حجم/نوع، مفتاح مخصص، تدوير المفتاح ومراقبة الحصة |
| Firestore direct writes من المتصفح | تعديل بيانات غير صحيح إذا كانت القواعد واسعة | متوسط | قواعد مدير صارمة، اختبارات Emulator، تحقق حقلي |
| طلب مزدوج بسبب retry | شحن/معالجة مكررة | متوسط | idempotency key لاحقًا، منع الزر أثناء الإرسال، اختبار duplicate |
| صورة خارجية لا تستجيب | Hero أو غلاف مكسور | متوسط | معاينة fallback، URL validation، صورة بديلة |
| حذف سجل مكتبة لا يحذف ImgBB | بقاء ملفات orphan | متوسط | توثيق السلوك الحالي، إضافة حذف ImgBB اختياريًا بعد اختبار delete URL |
| إعادة تسمية تصنيف جزئية | كتب بتصنيفات غير متسقة | متوسط | batch/transaction، snapshot قبل وبعد |
| انتهاء جلسة المدير | فقدان حفظ أو رسالة غير واضحة | متوسط | اختبار token expiry، إعادة تسجيل الدخول، عدم فقد النموذج محليًا |
