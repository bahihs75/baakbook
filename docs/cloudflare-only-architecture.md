# بنية Baak Books بعد إيقاف Firebase

## القرار

سيُرحّل Baak Books إلى بنية Cloudflare متكاملة بدل Firebase:

| الطبقة | الخدمة | المسؤولية |
|---|---|---|
| الواجهة | Cloudflare Pages | نشر واجهة المتجر ولوحة الإدارة والملفات الثابتة على `baakbook.pages.dev` إن كان الاسم متاحًا |
| API | Pages Functions / Cloudflare Workers | تنفيذ الطلبات، التحقق من المدخلات، إعادة حساب الأسعار، صلاحيات الإدارة، واكتشاف الكتب |
| قاعدة البيانات | Cloudflare D1 | تخزين المنتجات والتصنيفات والطلبات والإعدادات وسجل الصور بصيغة SQLite/SQL |
| الصور والملفات | Cloudflare R2 | مكتبة صور الكتب ورفع الصور بدل ImgBB في النسخة الجديدة، مع إبقاء روابط الصور الحالية كخيار توافق |
| حماية النماذج | Cloudflare Turnstile | تقليل الطلبات الآلية والاحتيالية على نماذج الطلب والإهداء ورفع الصور |
| إدارة المشرف | Worker secrets + حماية وصول إدارية | عدم وضع رمز الإدارة أو المفاتيح داخل الواجهة أو المستودع |

## لماذا هذه البنية

تسمح Pages Functions بتشغيل كود خادمي على شبكة Cloudflare، ويمكن ربطها بـ D1 وR2 من خلال bindings متاحة في `context.env`. لذلك تستطيع الواجهة نفسها استدعاء API محليًا أثناء التطوير ثم استدعاء Functions بعد النشر، دون فتح قاعدة البيانات مباشرة للمتصفح [1] [2].

D1 قاعدة SQL مبنية على SQLite، وهذا يجعل تحويل `data.json` إلى جداول وعلاقات قابلة للفحص والتصدير أكثر وضوحًا من تخزين JSON كبير في مستندات منفصلة. سنحتفظ بالمعرّفات التاريخية وننشئ جداول منفصلة للمنتجات والطلبات وبنود الطلبات والمستلمين وسجل الصور [3].

R2 مناسب لملفات الصور غير المهيكلة. ستتعامل Function مع الرفع، وتتحقق من النوع والحجم والامتداد، ثم تسجل المفتاح والرابط وحالة الأرشفة في D1. لن يرفع المتصفح إلى R2 مباشرة من دون مسار موثوق أو رمز رفع محدود.

## حدود الأمان

لن يثق API بسعر أو إجمالي ترسله الواجهة. سيرسل العميل معرّفات المنتجات والكميات وبيانات الهدية، ثم يعيد Worker قراءة السعر وحالة التوفر ومدة الاقتناء من D1 وإعادة الحساب قبل إنشاء الطلب. سيُستخدم مفتاح idempotency لمنع إنشاء الطلب مرتين عند إعادة إرسال النموذج.

سيكون المتجر العام للقراءة من API محدد ومحدود، بينما ستكون الكتابة مقتصرة على مسارات الطلب والإهداء والرفع والإدارة. ستُفصل صلاحيات الإدارة عن الواجهة، وستوضع الأسرار في Cloudflare Secrets لا في GitHub أو ملفات JavaScript عامة.

## مسار الطلب

1. يرسل المتصفح منتجات وكميات وبيانات مستلم الهدية إلى Function.
2. يتحقق Turnstile من الطلب عند تفعيل الحماية.
3. يقرأ Worker المنتجات من D1 ويعيد حساب الأسعار والتوصيل والتوفر ومدة الاقتناء.
4. ينشئ Worker الطلب وبنوده في D1 ضمن عملية متسقة مع مفتاح idempotency.
5. يعيد رقم الطلب وحالة الاستلام للواجهة.
6. تظهر الطلبات في لوحة الإدارة بعد حماية مسار الإدارة.

## مراحل التنفيذ المحلية

لن ننشئ موارد Cloudflare أو نرفع بيانات حية قبل إكمال هذه الملفات محليًا:

1. مخطط SQL كامل ومحوّل حتمي من `data.json` إلى SQLite/D1.
2. فحص مصدر مستقل وفحص هدف مستقل مع مقارنة العدادات والبصمات.
3. Functions متوافقة مع عقد الواجهة، تشمل المتجر، الاكتشاف، الطلبات، الإهداء، والإدارة.
4. ربط الواجهة المنفصلة بـ API محلي يحاكي D1 وR2.
5. اختبار الأمان، التكرار، الأسعار، الإهداء المختلط، ومدة الاقتناء.
6. حزمة قطع نهائي تتضمن تجميد PythonAnywhere، تصديرًا نهائيًا، فحصًا مزدوجًا، واستيرادًا واحدًا فقط.

## ما سينشئه المستخدم لاحقًا من Cloudflare Dashboard

بعد اكتمال البناء المحلي سيُطلب إنشاء D1 وR2 ومشروع Pages وربط GitHub من لوحة Cloudflare. يجب تنفيذ هذه الخطوة فقط بعد مراجعة الملفات والأسماء. سنستخدم الاسم المقترح `baakbook` لمشروع Pages، لكن عنوان `baakbook.pages.dev` يبقى مشروطًا بتوفر الاسم في حساب Cloudflare.

لا يحتاج D1 إلى Firebase، وهو متاح على Workers Free ضمن حدود الاستخدام المعلنة. أما Workers Paid فيتضمن رسمًا شهريًا أساسيًا قدره 5 دولارات وفق الوثائق الحالية، لذلك لن نفعّل خطة مدفوعة دون موافقة صريحة [4].

## ملاحظة تنفيذية موثقة — D1 transactions

توضح وثائق Cloudflare الرسمية أن `D1Database.batch()` يرسل عدة عبارات SQL داخل استدعاء واحد، وأن العبارات المجمعة تُنفّذ كمعاملة SQL؛ لذلك سيستخدم Worker `batch()` في إنشاء الطلب وتسجيل بنوده وتحديث المخزون ومفتاح منع التكرار بعد إجراء التحقق الخادمي. المصدر: https://developers.cloudflare.com/d1/worker-api/d1-database/

وتوضح وثائق Cloudflare الخاصة بربطات Pages أن Pages Functions يمكنها الوصول إلى D1 وR2 عبر bindings، بحيث لا تُكشف موارد قاعدة البيانات أو التخزين مباشرةً للمتصفح. المصدر: https://developers.cloudflare.com/pages/functions/bindings/
