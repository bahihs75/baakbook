# تقرير تحقق Firestore Emulator المحلي

## نطاق الاختبار

أُجري الاختبار داخل مشروع Baak Books المحلي فقط باستخدام Firebase Emulator ومعرّف تجريبي هو `demo-baakbook`. لم يُستخدم المشروع الحقيقي `baakbook-77c00`، ولم تُرسل أي بيانات إلى Firebase السحابي.

## النتائج

| الاختبار | النتيجة | الملاحظة |
|---|---:|---|
| تحميل `firestore.rules` داخل Emulator | ناجح | القواعد قُرئت من الملف المحلي |
| كتابة بيانات الاختبار | ناجحة | تمت عبر ترويسة Emulator الخاصة بالزرع الاصطناعي فقط |
| قراءة منتج نشط دون مصادقة | ناجحة | سمحت القواعد بالقراءة العامة |
| قراءة منتج مخفي دون مصادقة | مرفوضة | أعاد Emulator `403` |
| كتابة منتج دون مصادقة | مرفوضة | أعاد Emulator `403` |
| `GET /api/products` عبر Pages | ناجح | أعاد المنتج النشط ولم يعرض المنتج المخفي |
| `GET /api/products/:id` عبر Pages | ناجح | أعاد المنتج النشط بعد ربط Pages بـ Emulator |
| `GET /api/admin/products` دون توكن | مرفوض | أعاد Pages `401` قبل الاتصال بالخدمة الإدارية |
| `OPTIONS /api/products` | ناجح | أعاد `204 No Content` بلا جسم غير صالح |
| تنظيف العمليات والمنافذ | ناجح | لم تبقَ عمليات Firebase أو Wrangler بعد السكربت |

## طريقة إعادة الاختبار

يُعاد تشغيل الاختبار من جذر المشروع بالأمر الآتي:

```bash
./scripts/test_pages_firestore_emulator.sh
```

السكربت ينشئ Emulator مستقلًا، ويستخدم `demo-baakbook`، ويزرع كتابين اصطناعيين، ثم يشغل Pages على المنفذ `8790` ويجري فحوص المسارات والقواعد. عند الانتهاء ينظف مجموعات العمليات المؤقتة تلقائيًا.

## حدود النتيجة

هذا الاختبار يثبت **اتصال Pages المحلي بـ Firestore Emulator وتطبيق القواعد الأساسية**. لا يثبت بعد صحة بيانات الإنتاج، ولا صلاحيات Firebase Authentication الحقيقية، ولا إنشاء الطلب عبر Firebase Function المنشورة؛ تلك البنود تحتاج إعدادًا واختبارًا منفصلًا بعد تجهيز الخدمة الموثوقة وبموافقة صريحة قبل أي استخدام إنتاجي.

كما أن ترويسة `Authorization: Bearer owner` الموجودة داخل سكربت الزرع مخصصة لـ REST Emulator لكتابة fixtures اصطناعية فقط، ولا يجوز استخدامها في Pages أو Firebase Functions أو أي بيئة إنتاجية.
